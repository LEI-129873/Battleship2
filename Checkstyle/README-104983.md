# Checkstyle – ConstantName

Regra `ConstantName` (`checkstyle-104983.xml`): as constantes (campos `static final` e campos de interfaces) têm de estar em `UPPER_CASE`, com as palavras separadas por `_`. Padrão: `^[A-Z][A-Z0-9]*(_[A-Z0-9]+)*$`. O workflow `.github/workflows/checkstyle-constant-104983.yaml` usa `dbelyaev/action-checkstyle@v4.5.0` (Checkstyle 14.4.0), com `filter_mode: nofilter` para verificar todos os ficheiros e `fail_level: error` para o job falhar quando há violações.

## Execuções

Violação provocada no PR [#45](https://github.com/LEI-129873/Battleship2/pull/45), com a constante `maxShips` em `Game.java`:

- Gate a falhar: https://github.com/LEI-129873/Battleship2/actions/runs/42536244141. Indica `Game.java:152`, *"Name 'maxShips' must match pattern '^[A-Z][A-Z0-9]*(_[A-Z0-9]+)*$'"*.
- Gate a passar (constante renomeada para `MAX_SHIPS`): https://github.com/LEI-129873/Battleship2/actions/runs/42536570041

## Proteção do ramo `main`

O ruleset `main` exige o check `Checkstyle ConstantName 104983` antes do merge. A regra foi adicionada pelo dono do repositório, porque a conta 104983 não tem permissões de administração. Com a violação, o PR #45 ficou com o estado `BLOCKED`, e era o único dos 8 checks exigidos a falhar. Depois da correção, o merge ficou disponível. O PR de demonstração foi fechado sem merge.

## Limitações do Checkstyle

O Checkstyle só verifica a forma do nome com uma expressão regular: `MAX_SHIPS` e `X` ou `VALOR_2` passam da mesma maneira, embora só o primeiro seja significativo. Também não avalia se um valor devia ser uma constante, por exemplo um número mágico usado diretamente no código, nem se o nome corresponde ao significado do valor. Além disso, a regra só se aplica a campos `static final`: um campo `final` de instância com valor fixo, que na prática é uma constante, não é verificado.
